# k6-Style Profiler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可对比 C 版（`../yar-c`）与 Rust 版 yar 的 k6 式基准：2C/2G 双容器（server + profiler），VU 与 body 双梯度压测，输出 QPS/成败/分延迟/容器 CPU·内存报告。

**Architecture:** 库内 `server.rs` 补真实资源控制 (`max_inflight` Semaphore + `max_request_size` 前置校验)；新增 `src/profiler.rs` 压测库 + `src/bin/profiler.rs` CLI + `src/bin/yar-server-rust.rs` echo 服务入口；`profile/` 下 C echo server、两个 almalinux 基座 Dockerfile 与驱动脚本 `run.sh`（负责容器编排、cgroup 轮询、CSV 合并）。

**Tech Stack:** Rust std + tokio（既有依赖，零新增）；C 侧 libevent + msgpack-c(cpp-3.2.0)；podman（`--cpus=2 --memory=2g --network=host`）。

**Spec:** `docs/superpowers/specs/2026-10-31-profiler-design.md`（本计划 arges from spec；执行者须同读 spec）

## Global Constraints

- 不新增任何 Cargo 依赖（profiler 仅用 std）。
- 不修改 `../yar-c` 的任何文件；所有对它的一次性改动只发生在 run.sh 生成的临时构建目录。
- 两个 Dockerfile 的 builder 与 runtime 基座均为 `docker.io/library/almalinux:latest`。
- 容器资源：server 与 profiler 各 `--cpus=2 --memory=2g --memory-swap=2g --network=host --ulimit nofile=65536`（run.sh 统一施加）。
- echo 接口语义：`p`（实为数组，含 1 个长度为 N 的字符串）被服务端**原样**作为 `r` 返回；两端实现方式均为"把解析树 push_data 进返回包"（内存行为同阶）。
- 两端 server read timeout 统一 5s；Rust 服务端 `--read-timeout 5s` 默认即 5s；C 版 `YAR_READ_TIMEOUT` 默认 5s 不改。
- `max_request_size` 默认 `8 * 1024 * 1024`（8 MiB）；profiler 只发 ≤4M body，两端服务端对超限请求回 status≠0 错误响应并关闭连接。
- worker 容量对齐：C 版由 `-n N` 传 max_children，Rust 版 `--inflight N`（0=不设限），run.sh 对两版传同一个 N（默认 2）。
- 报告 CSV 列固定：`size_bytes,vus,duration_s,qps,ok,fail,p50_ms,p95_ms,p99_ms,p999_ms,first_error`；VU 从 10,20,40,80,160,320,640；body 阶梯 `256b,1k,4k,16k,64k,256k,512k,1m,2m,4m`（两个默认列表均 CLI 可覆盖）。
- 阶梯切换：每档结束先静默 1s 再进下一档；每 VU 持久连接（`set_persistent(true)`）。

## Review Focus

1. 超大 `body_len` 恶意头部（如标 1GiB）：服务端必须在**读 body 之前**回错误响应并关闭，不得按 body_len 预分配/整读 —— Task 1 测试钉住。
2. `max_inflight` 排队语义：超限连接是**等待**而非拒绝；前一个连接释放后能立刻被处理 —— Task 2 测试钉住。
3. 零样本分位数：`p50/p95/p99/p99.9` 对空样本返回 0.0，不得 panic —— Task 4 单测钉住。
4. echo 完整性：4M 顶格 body 的响应其 `r[0]` 字节长度必须精确等于 N（任务内用 1M 顶格验证，run.sh 端到端再验 4M）—— Task 4 集成测试 + Task 8 端到端钉住。
5. 档间隔离：第二档必须使用**新建**连接，上一档连接已全部收尾（防持久连接态泄漏）—— Task 4 集成测试钉住。
